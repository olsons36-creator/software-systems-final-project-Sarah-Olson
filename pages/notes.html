Software Systems Notes


Html- hypertext markup language

Attributes: provide additional info about an element (class, id, href)


Css- cascading style sheet

Class- used on multiple elements

Id- unique, used to identify a single element

.class #id


Css selector is based on specificity (more specific → higher priority)


External css is linked in the header

Internal css is written in the head element

Inline css is the style attribute of an element


    h2{
        color: red;
        background: white;
    }

***CSS needs the semicolon after every property

DOM (Document object model)

The Dom is the browser’s representation of a webpage

Every element on the page becomes a part of the DOM












Software development life cycle:

From the initial idea to the finished product

  • Plan → decide what needs to be built
  • Build → create the software
  • Test → find & fix the problems
  • Release → deliver the software
  • Improve → make changes based on feedback

Creating websites

Waterfall: work moves through planned stages in a fixed sequence. Finish one stage before moving on to the next

Agile- focuses on building in small pieces, getting feedback, and adapting. Work is divided into smaller chunks


Minimum Viable Product- simplest working version of a product built with just enough core features to solve problems


Version Control- Git

Is a system that tracks changes made to files over time

Can save & track changes, revert to previous changes, collaborate, branching & merging


Local Branch → Remote Feature Branch → Dev → Main


  • Local branch- safe, stored on your device
  • Remote feature branch- same content as local branch, but is online, safe from customers, but your peers can view (doesn’t happen often)
  • Dev branch- collaborative space, all code sent to dev must be tested and reviewed (dev is usually made by the company)
  • Main branch- final resting place for your code, customers can see and interact with the code
